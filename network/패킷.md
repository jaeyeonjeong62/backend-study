>**메세지 생성의 논리적 과정**
>1. Application Layer에서 http메시지가 생성된다(사용자가 사용하는 프로그램에서 생성된다.).
>2. Transport Layer에서 PORT정보, Network Layer에서 IP정보 등이 담긴다.
>3. 최종적으로 LAN카드를 통해 인터넷으로 전기신호로 변환되어 인터넷 회선에 전달된다.


**IP 프로토콜**

- 복잡한 인터넷망에서 목적지로 보내기 위해 IP주소를 사용하여 데이터를 전달

- IP 프로토콜의 한계
    - 패킷을 받을 대상 서버가 불능이거나, 중간에 패킷이 소실될 수 있음(비연결성)
    - 패킷의 순서가 보장되지 않음
    - 서버에 여러 애플리케이션이 떠 있을 때 구분의 문제(PORT를 사용하지 않아서 발생하는 문제)
    - 즉, 같은 IP에 여러 프로그램의 구분 문제 발생

- IP방식의 또 다른 한계와 DNS 등장
    - IP는 사용자 입장에서 기억하기 어려운 문제
    - 또한, IP주소는 서버의 사정으로 언제든 변경될 수 있는 문제점이 존재
    - DNS(Domain Name System)의 등장
        - 글로벌한 네임서버에 IP주소를 등록해두고 사용자에게는 도메인만 알려주는 방식
        - 사용자가 도메인을 통해 요청하면, DNS서버에서 도메인명을 IP주소로 변환

**TCP 프로토콜의 등장**

- PORT정보를 담아 전송함으로서 한 서버 내 애플리케이션 구분 문제 해결

- 전송 순서를 담고 있는 규약을 통해 전송의 순서 보장

- PORT
    - 같은 IP 내에서 프로세스 구분의 역할
    - 0 ~ 65535 범위에서 할당 가능
    - 0 ~ 1023은 Well Known Port
        - 이미 정해져 있는 포트이므로 별도로 사용하지 않는 것이 좋음
        - FTP $\rightarrow$ 20, 21
        - TELNET $\rightarrow$ 23
        - SSH $\rightarrow$ 22
        - HTTP $\rightarrow$ 80
        - HTTPS $\rightarrow$ 443

**MAC주소와 IP주소**

MAC주소는 네트워크 장비(랜카드)에 부여된 고유 번호
```
A4-B1-C2-D3-E4-F5
```

IP주소는 네트워크에서 장비의 위치를 나타내는 주소

ARP는 IP주소를 MAC주소로 변환해주는 프로토콜
```
arp -a
```
외부 서버로 통신할 때는 외부 서버의 MAC주소를 찾는 것이 아니라, 우선 같은 네트워크에 있는 기본 게이트웨이, 즉 공유기의 MAC주소를 찾는다.

```
netstat -n
# 프로그램의 PID까지 확인하려면 다음 명령어를 사용합니다.
netstat -ano
# LISTENING 상태인 포트는 외부 접속을 기다리고 있는 열린 문과 같습니다. 
# 사용하지 않는 포트가 열려 있다면 보안 점검 대상이 될 수 있습니다.
netstat -an | findstr LISTENING
```

**TCP와 UDP**

|항목|TCP|UDP|
|---|---|---|
|연결|먼저 연결함|연결하지 않음|
|수신 확인|확인함|확인하지 않음|
|재전송|손실 시 재전송|재전송하지 않음|
|순서 보장|보장함|보장하지 않음|
|속도|상대적으로 느림|빠름|
|사용 예|웹,메일,파일 전송|DNS,스트리밍,온라인 게임|

**3-way Handshake**

TCP는 데이터를 보내기 전에 연결을 먼저 맺는다.
```
SYN → SYN + ACK → ACK
```

**TCP 연결 과정**

1. 3-way Handshake (SYN → SYN + ACK → ACK)
2. 데이터 전송 (DATA → ACK)
3. 4-way 종료 (FIN → ACK → FIN → ACK)

**UDP 연결 과정**

1. 시작
2. 전송
3. 손실
4. 마무리
